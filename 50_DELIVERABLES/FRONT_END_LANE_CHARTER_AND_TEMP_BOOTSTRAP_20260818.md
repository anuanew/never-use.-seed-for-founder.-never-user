You did not describe ten sites. You described **two shells and N stations**, which is a completely

F6.3: *"she's like the independent thinking station and the experience on the front end."*

**The porting answer, and it is the whole trick:**

> **A station is built as a slot, never as a page.**

The shell owns the chrome: header, menu, nav, threading, drilldown, window controls on the left, the
one-iframe rule, per `R4` F2.2. The station owns only its own body and its own wonder.

Then *"port the budget one into computer-and-browser"* is not a port at all. **It is a registration.**
The budget station never had a header to duplicate, because it was never allowed to own one. It renders
into a slot the shell already owns, and it inherits every convention automatically. Build it once for
GMGU, register it into both shells, and no menu is ever written twice.

This is also why F2.2's *"no iframes between apps, kernel pattern instead"* is in the settled-conventions
list. An iframe would let a station bring its own chrome. The kernel pattern does not.
